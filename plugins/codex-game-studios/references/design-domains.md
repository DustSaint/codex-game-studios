# Design domain lenses

Load only the lenses relevant to the request.

## Combat and action

Check input timing, anticipation, active and recovery windows, hit rules,
interruptions, invulnerability, targeting, camera, feedback, resource economy,
difficulty scaling, enemy readability, and deterministic replay needs.

## Economy and progression

Map sources, sinks, faucets, gates, caps, conversion rates, inflation risks,
loss aversion, catch-up rules, progression pacing, reset behavior, exploits,
and the data needed to tune or monitor the system.

## Level and encounter

Define spatial grammar, navigation, encounter beats, intensity curve, teaching
sequence, checkpoints, failure recovery, content dependencies, accessibility,
and how representative player paths will be tested.

## Narrative

Define narrative purpose, state and branching ownership, re-entry and skip
behavior, localization budget, gameplay interruption cost, consequence
visibility, save compatibility, and how narrative state affects systems.

## UX and accessibility

Define task flow, information priority, input methods, focus and navigation,
error prevention and recovery, text scaling, contrast, motion alternatives,
audio-independent cues, remapping, onboarding, and platform conventions.

## Art, animation, and audio

Define functional intent before asset format: silhouette, readability, timing,
style constraints, variants, states, technical budget, naming and ownership,
fallbacks, source-file policy, import validation, and in-engine acceptance.

## Live and social systems

Define authority, identity, privacy, moderation, abuse cases, time zones,
offline and reconnect behavior, season boundaries, rollback, observability,
economy impact, and operational ownership. Do not perform external live
operations without explicit user authorization.
