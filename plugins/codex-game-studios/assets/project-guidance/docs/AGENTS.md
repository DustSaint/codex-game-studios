# Documentation guidance

- Keep requirement and decision identifiers stable once referenced.
- Record why a consequential decision was made, alternatives considered,
  consequences, validation, and the condition for revisiting it.
- Distinguish current behavior from proposals and future work.
- Link evidence to the exact criterion it supports and state anything not run.
- Update dependent documents when ownership, APIs, formulas, or acceptance
  criteria change; do not erase superseded decision history.
