# Design guidance

- Specify player intent, inputs, state, rules, outputs, feedback, tuning,
  dependencies, edge cases, and observable acceptance criteria.
- Define variables, units, ranges, rounding, and examples for every formula.
- Keep implementation choices out of behavior specifications unless they are
  accepted product constraints.
- Propagate accepted changes to affected systems, UX, content, analytics,
  saves, tests, production plans, and related documents.
- Mark unresolved questions and decision owners explicitly.
