# Codex Game Studios

[English](README.md) | [简体中文](README.zh-CN.md) | [Русский](README.ru.md) | [Deutsch](README.de.md) | [日本語](README.ja.md) | [한국어](README.ko.md)

![Баннер Codex Game Studios](assets/branding/codex-game-studios-banner-minimal.png)

Codex Game Studios — это нативный для Codex фреймворк разработки игр,
адаптированный из
[`donchitos/claude-code-game-studios`](https://github.com/donchitos/claude-code-game-studios).
Он сохраняет полезные процессы разработки игр из исходного проекта, заменяя
специфичные для Claude роли, уровни моделей, хуки и передачу команд нативными
Skill Codex и явными границами доказательств.

Плагин охватывает разработку концепции, проектирование игры и отдельных функций,
технический дизайн, реализацию, ревью дизайна и кода, планирование QA, анализ
плейтестов, производственное планирование и сквозную координацию разработки.
Перед технической работой он определяет Unity, Unreal, Godot, браузерный или
неизвестный проект и только после этого выбирает соответствующий адаптер движка.

## Установка

Добавьте маркетплейс и установите плагин с помощью Codex CLI:

```powershell
codex plugin marketplace add DustSaint/codex-game-studios --ref main
codex plugin add codex-game-studios@codex-game-studios
```

После установки начните новую задачу Codex, чтобы новые Skill были обнаружены.

## Использование

Для широких задач по разработке игр явно вызывайте координатор:

```text
$codex-game-studios:manage-game-development
```

### Частые вызовы

| Вызов | Назначение |
| --- | --- |
| `$codex-game-studios:brainstorm-game-concept` | Разработка игровой концепции |
| `$codex-game-studios:design-game` | Целостный дизайн игры и связанных систем |
| `$codex-game-studios:design-game-feature` | Спецификация отдельной функции |
| `$codex-game-studios:write-game-technical-design` | Технический дизайн и архитектура |
| `$codex-game-studios:implement-game-feature` | Реализация функции |
| `$codex-game-studios:review-game-design` | Ревью игрового дизайна |
| `$codex-game-studios:review-game-code` | Ревью игрового кода |
| `$codex-game-studios:plan-game-qa` | Планирование QA |
| `$codex-game-studios:analyze-game-playtests` | Анализ отзывов и данных плейтестов |
| `$codex-game-studios:plan-game-production` | Вехи и производственное планирование |

Если границы задачи достаточно ясны, её можно описать естественным языком —
Codex автоматически выберет подходящий Skill.

## Поддерживаемые движки

| Среда выполнения | Поддержка |
| --- | --- |
| Unity | Встроенный адаптер для технического дизайна, реализации функций, ревью кода, жизненного цикла движка и правил верификации |
| Unreal Engine | Встроенный адаптер для технического дизайна, реализации функций, ревью кода, жизненного цикла движка и правил верификации |
| Godot | Встроенный адаптер для технического дизайна, реализации функций, ревью кода, жизненного цикла движка и правил верификации |
| Браузерные игры | Определяет браузерный проект и передаёт работу с конкретным фреймворком установленным Game Studio Skill для Phaser 2D, Three.js/WebGL или React Three Fiber |
| Неизвестные или противоречивые признаки | Сохраняет нейтральность к движку и запрашивает недостающие сведения о проекте вместо догадок |

Работа над концепцией, общим дизайном и дизайном функций остаётся независимой от
движка, если его ограничения не меняют наблюдаемое игроком поведение. Технические
процессы определяют версию движка по файлам проекта и проверяют нестабильные API
по официальной документации этой версии.

## Безопасность и границы

- Установка не изменяет игровые проекты и не регистрирует хуки жизненного цикла
  или командной оболочки.
- Внешние действия, включая commit, push, развёртывание, загрузку в магазин и
  выпуск релиза, требуют явного разрешения пользователя.
- Результаты QA остаются в состоянии `NOT RUN`, пока не появятся проверяемые
  доказательства; непроверенная работа никогда не объявляется успешно пройденной.
- Дополнительные инструкции для проекта копируются только по запросу пользователя.
- Специализированная работа для браузера и Godot передаётся отдельно установленным
  официальным или профильным Skill, когда они доступны; при их отсутствии
  используется явный запасной процесс с описанными ограничениями.
